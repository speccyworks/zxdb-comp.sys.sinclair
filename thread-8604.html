1997-02-18 …@… 

  It seemed necessary to include a Standard PAUSE after Data block. By default
Spectrum ROM Save routine would make a 1s pause between Header and Data block.
So there is now no need to put a Pause block (01) after each and every Data
block in the tape. The Pause block should only be used if the pause should be
significantly bigger or very small or the standard pause is to be changed for
all blocks. You can ofcourse change the standard pause in the beginning to
gain some seconds from loading time. If there is no pause block following a
data block then the standard pause is used.

PLEASE Don't use this format until it has been approved by most of the emulator
writers and it proves to be OK for everyone ... :)


                             ZX Tape file format
                            ---------------------
                                   v 0.1

  This format lets you preserve all (hopefully) of the tapes with turbo or
custom loading routines. Even though some of the newest and 'smarter' emulators
can find most of the info about the loader from the code itself, this cannot be
possible if you want to replay the file to the good old real spectrum. And with
all this information in the file the emulators don't have to bother with finding
out the baud rate and other things.

  Please suggest a extension for this format (3 letters) , since .ZXT is already
taken by some other tape format with +3DOS info.

  The file is identified with the first 6 bytes being 'ZXTape'. Then the body
follows which is devised from blocks. Each block is identified with its ID
byte followed by its body. There are currently 4 types of blocks.

So the file structure is :  'ZXTape' ID1 Body1 ID2 Body2 ...
                             0       6   7     ...

  The Two-Byte (Word) values are always stored LSB (Least Significant Byte)
First.
  The timings are given in Z80 clock ticks (or T states) unless otherwise
stated.   1 T state=1sec/3500000   !
  The values in the tables mean : Offset (in bytes), Length (in bytes
(i.e. 1 - byte, 2 - word)) and then the description.
  You might interpret full-period as one pulse (----____ or ____----) and
half-period as only one half of the pulse (---- or ____).
  The values in brackets [] are the Default values for Spectrum ROM loading/
saving routines.

These are the possible blocks :

ID : 00  -  Change of Loading Speed
-------     If this block is never present then all blocks are saved with normal
            speed. If my default values are incorrect then please inform me !

00 2  Length of PILOT half-period     [2100]
02 2  Length of SYNC  half-period     [700]
04 2  Length of 0-bit half-period     [800]
06 2  Length of 1-bit half-period     [1600]

ID : 01  -  Pause
-------     With this block you can change the Standard Pause which is used
            after ALL Data blocks in the tape or you can change the pause
            only for this one time. If the tape should be stopped at this
            point then use the Indefinite Pause and the program will wait for
            you to tell it to continue loading. The Pause of 0 miliseconds
            will immediately start loading next block.

00 1  Type of Pause :  00 - Change Standard Pause after Blocks   [1000]
                       01 - Use this Pause only for this Block
                       02 - Indefinite Pause (i.e. waiting for a key press)
01 2  Value in miliseconds (ms)  -  if Type is 02 then value should be 0000

ID : 02  -  Text Description
-------     The description can be upto 255 characters long but please keep
            it down to about 30 so the programs can show it in one line !
            This is ment to identify parts of the tape, so you know where
            level 1 starts, where to rewind when you lose all the lives, etc.
            Of course you can use it in the beginning to identify the name of
            the game or program used in the file.

00 1  Length of the Text
01 x  Text in ASCII

ID : 03  -  DATA Block
-------     This is the block with actual data. It is very similar to the .TAP
            block but with some additional Info.

00 2  Length of PILOT tone (in PILOT full-periods)     [4000 Header, 2000 Data]
02 1  Length of SYNC tone (in SYNC full-periods)       [1]
03 1  Used bits in LAST Byte (other bits should be 0)  [8]
      i.e. if this is 6 then the bits (x) used in LAST byte are: xxxxxx00
04 1  Starting wave (the Amplutude of FIRST half-period):   00=Low  FF=High
      i.e. if the first pulse of PILOT starts with ____ (00) or ---- (FF)
05 1  Reserved
06 2  Length of DATA that follows
08 x  DATA, the bits are saved MSb (Most Significant Bit) first

ID : 05  -  Hardware Type
-------
          This selects what hardware the programs on this tape use. One program
          can run on 48k and use AY sound and when run on 128k speccy use its
          memory. Every Hardware Type has its own bit in the double-byte word.
