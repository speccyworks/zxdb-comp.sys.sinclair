The superfast circles I was talking about look just as good as floating 
point ones but *calculations* to reproduce floating point preciseness 
are very simple and integer.

The algorithm is based on the fact that when the y coord is increased, 
there is only a decision if to decrease the x coordinate or not (the 
coords are calculated for only first 45 degrees). So, starting from 
(r,0) very next coordinate is going to be either (r,1) or (r-1,1) etc..

Everytime we have (x,y) coordinates of a circle pixel, the very next 
pair is (x,y+1) or (x-1,y+1). Algorithm checks (in a very cleaver&fast 
way) which coordinate pair better fits in the

x*x + y*y = r*r

So the circles are *perfect* and very fast ('instantaneous').

2010-02-17 17:02:31 jgharston Re: ANN: SE Basic Beta 2
On 17 Feb, 08:20, OwenBot <…@…> wrote:
> mode). Hopefully I'll get a chance tonight. Does & support variable
> length, in the same way BIN does? It would be nice to be able to
> return something valid for &n, &nn, &nnn, and &nnnn.

Yes, & is a prefix to say 'start reading as hex until nonhex digit'
in the same way that BIN is says 'start reading as binary until
nonbinary digit'. The code in the Harston ROM doesn't check for
overflow, so &12345 evaluates as &2345, but that was ok enough for
me to be able to do things like SAVE "scrn",CODE &8000,&1B00,&4000.

It works by diverting the line scanning code at &2684 and
instead of CALLing to check for a numeric, it CALLs to
check for a hex or numeric. The new subroutine checks for
a '&', if not present, continues to the old decimal code,
if present, steps through following characters doing
acc*16+next until it encounters a non-hex character, and
then returns in the same way as returning from scanning
a decimal number.

STR$~ works by co-opting the unusable calculator function
&3C (unusable as it expects a parameter in the A register).
New calculator op &3C replaces top-of-stack with hex string.
Evaluation of STR$ at &2707 checks for a following ~ character
and uses calculator op &2E for STR$ and &3C for STR$~.
