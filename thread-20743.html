2001-02-05 00:16:01 Joe Mackay Re: I'm all for realism, but this is ridiculous...
Chris Young <…@…> wrote:
> Is it really necessary to emulate loading games at Spectrum speed,
> complete with authentic coloured stripes and loading noise?

With TZX files, well, basically, yes. But with exceptions.

To make the emulation of custom loaders as accurate as possible, the
emulated Speccy has to be perfectly in sync with data from the 'tape'.
So, unlike .TAP files, it's not simply a matter of intercepting the
ROM's load routine and blamming the data into memory quickly. To
speed up the loading you have to speed up the whole emulation.

If the TZX file only contains "normal" blocks, though, some emulators
can treat them like TAP file blocks and load them quickly. There's
also one or two emulators (I think) that can cope with some custom
loaders, but I don't know how well they work.

> [1] Actually, I've just remembered that x128 has a loading speed
> setting, which may do exactly this.  Perhaps I should check these
> things before moaning about them, eh?

Yes. But X128's setting just adjusts the speed of the whole emulation
while things load. It can still take ages.

OTOH, one thing I meant to add to my original reply to the post, was that 
back in the day when I started with speccy emulation (with Z80 v2.1 i 
believe), The ONLY way I had to get speccy games (I had no home internet 
connection, and couldn't download to disk at university), was to use the 
Z80 LPT interface and load the games manually from tape myself. Now THAT 
was a nostalgic experience, not just the speed of TZX, but the noise, 
frustration (of vol/tone levels), and the 'R Tape Loading error's :)

One thing that annoys me about emulation (I suspect it does to many others 
too, though maybe they haven't noticed yet :) is that no matter which 
platform is being emulated, I seem to have less patience when dealing with 
emulation than the real thing. I'm more tempted to load up a ROM/Snap/Disk-
Image and play for 30 seconds, then move on to something else, whereas with 
the real thing, I'd tend to play for a serious amount of time, even if it 
wasn't my favorite game. This is the reason why I'm starting to seek out 
the REAL systems rather than emulate - so far I've gotten myself a A1200 
and 520ST which covers the 16bit computer bases. As expected, when I loaded 
up Populous on the A1200, I played it for about 4 hours, compared to 45 
minutes being my longest duration of Populous play on UAE (and yes, I did 
say i prefer pop. on the ST, but my ST won't arrive til tomorrow thanks to 
UPS :/ But then I'll probably spend all my time playing Deuteros :)

I've been saying this since the start of the emulation days, but perhaps 
the load times encourage more persistance with a game, rather than just 
tossing it aside and trying something else.

The bottom line is that I still believe that while Emulation is pretty much 
100% accurate these days, it still doesn't match the experience of the real 
hardware. There's just 'something' different that makes the real thing more 
enjoyable. I'm sure many people on the group that still own a real spectrum 
agree, after all, if Emulation was the best solution, they probably 
wouldn't bother owning a speccy, and just make a killing on ebay like so 
many others :)

One day, I'm sure we'll be holding the same argument of old-style emulators 
vs complete-hardware emulators, where the hardware-spec type emulators are 
based on a generic emulation of the physical chips, and the latter offering 
a preservation format for the actual hardware (ie, it being physically 
possible to rebuild an 80s computer from its hardware definition :) But 
then it'll probably be 'why must people use the hardware format, when a 
soft-emulator can fix X bug in Y machine' *grin*

Well, you missed the point a bit. .VOC files are the ones that would
have the volume setting since they are the actual sound from the tape.
Speccy's hardware actually converts the sound into pulses (correct me if
I'm wrong, please), then the software measures the length of pulses and
decides what they mean (leader/pilot, bits, rubbish...). Therefore, if
you want to keep "everything" you can save the pulses instead of the
actual sound for the emulation since the software on the Speccy (loader)
can't read beyond pulses. However, if you save pulses and their lengths,
you make sure that they are timed acurately and save a lot of space. And
that's what .TZX is for. It can, of course, store the whole blocks with
the info which loader it is for, actually the info tells how long the
pulses in the leader and in the bits are. But it also allows pure
leader, a block of bits without leader, or even a raw sequence of
pulses[1], so it reaches the full generality. But it saves a lot of
space comparing to .VOC even if you actually use raw pulses for some
pervert purpose[1]. :-) That means no matter what kind of pervert loader
someone wrote and it worked on a Speccy, it will work on the emulator
that supports .tzx.

[1] I actually did it once. I've written a custom loader that would be
as fast as the routine could manage to follow the pulses. But ROM
loaders and custom loaders always asumed 2 pulses for a bit and that's
what .TZX format asumes, too, when you want a block. I, of course,
wanted only 1 pulse per bit since I double the loading speed limit. I
went even further, I suppressed the colour stripes while loading (but
kept them when detecting the leader), and (yes, you'll say I'm crazy) I
made every non-first bit in a byte shorter than first since the first
bit in every byte requires extra CPU work (writing the previously built
byte into memory, increasing address, ...). Since I didn't show colour
stripes while loading I saved registeres which made it possible to use
HL instead of IX for addressing - which also sped it up.
The leader was only something like 0.2 second long. To actually test the
loader, I couldn't put a custom block into a .tzx file (since they don't
allow <>2 pulses per bit and variable bit timing during loading) so I
had to put a raw sequence of pulses. However, noone would like to enter
a row of 6912*8 pulses manually so I've written a program that read the
.scr file and made a .tzx containing only the pure leader block and raw
sequence of pulses, apropriate for my loader. On X128 it actually
worked! :-) The whole picture was loaded in something like 2 seconds, I
think. But other emus didn't like it. Also, 44kHz sampling is not good
enough for the speed I reached so it didn't work at all if I converted
that .tzx to .voc. It would never work on the real Speccy. :-)
