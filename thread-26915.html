Actually, I think I will.  I think the most painless way for me
to do this would be to supply a precompiled binary that
would be copied into the final snapshot after the C project
is compiled.  I could then supply a C header and C wrapper
functions for calls to the SP API so that z88dk can compile
the project.  So project compilation would be a two step
process: run z88dk, then place a copy of the SP binary into
the final snapshot.

The one thing I have trepidations about is how much memory
a compiled C program needs and how easy it is to stop
the z88dk assembler from putting code into places used
by SP... I didn't manage to figure that one out from the docs.

Out of the box, SP-Spectrum leaves the following memory
available for user programs:

23296 -> 32255   (8960 bytes)
  Since you start with a snapshot
  Basic doesn't need any of this space.
32513 -> 32767   ( 255 bytes)
57120 -> 58318   (1199 bytes)

Between 32768 and 57120 there are (15048 bytes) available in
seventy-six 198 byte blocks.

Working with such a fragmented memory map is no problem from
assembly language, but for a C compiler, I don't know?  If
you've got some experience with this, let me know.

I'll put this near the top of my to-do list.  I don't think
it will take too long to do.

:-) Well, me too.  I loaded snapshots into my real machine
so I don't count that as ruling out original hardware.

Anyhow, the C lib is very close to completion; it will possibly
be done in the next day or two.  The entire assembly API
is available, including registration of a C function to run
on each interrupt.

The Spectrum version will have 9472 bytes available for
the C program, with lots more memory available elsewhere
which should be used to store graphics and other data.
The resulting program will be a tap file, so don't fret
over that one.

The next version of SP will be more friendly to z88dk
and won't have any upper memory limit (aside from the
size of the program of course).

The z88dk C kit is a real, pleasant surprise to me.  Dom
and the other developers deserve a pat on the back --
it is in really good shape.  I don't know why more speccy
enthusiasts don't try to write in C with such a good tool
available.  In fact, I'm going to plug it now:

http://z88dk.sourceforge.net/
