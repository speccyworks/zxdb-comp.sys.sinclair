OK, .Z80, .SNA etc are called "snapshots".  Basically, they're a dump
of the spectrums memory and registers at one moment in time.  To make
a snapshot, you'd load up your favourite game, then press the magic
button on a multiface (or it's emulated equivalent).

Later you could load the snapshot back into memory and the spectrum
would carry on at exactly the same point the snapshot was saved.

This format has it's advantages - you can make a snapshot at any point
in a game (not just the start). So, if you're stuck at some point in a
game, you could make a snapshot just before you get there.  After you
can keep reloading the snapshot and you'll start at that point without
having to replay all the previous levels etc.

However, it also has disadvantages.  Because the snapshot only
contains what is in memory at that point in time it, it doesn't
contain all the game information.  If a games was a multi-load, it
wouldn't contain the levels which are still to be played (Because they
haven't been loaded into memory yet). Likewise, it wouldn't have
things like the loading screen etc.

There are certain extensions to these formats to try and overcome
these problems, but I don't think they were every very well used (I
might be wrong).

.TAP format is really a recording of what the ROM SAVE routine outputs
to tape when a program is saving.  So, if a game is stored in .TAP
format, you can load it back into an emulator just like loading it
from tape.  All the parts of the program will be stored in the file
and multi-load program should work fine.

The problem with .TAP is that it only supports the standard tape
format that the ROM uses.  Games that used speed-loaders or any other
type non-standard loaded can't be stored in .TAP format (Without
hacking the program and converting it to a normal loader that is).

.TZX format is similar to .TAP (From the users perspective), It too
stores a record of what is stored on a tape. The difference is that it
supports many different types of loader.  .TZX keeps a record of what
type of speed-loaded the block uses and how it should be loaded back
in.

It is also extensible.  If a new program with a different type of
speed-loader is discovered, a new block type can be defines and
emulators can then be modified to handle this new type.

I hope this helps - I'm not an emulator writer myself (I merely enjoy
them) and I may be off with some of these descriptions but from a
users perspective, this is how it appears to me.

Tap: tape format
TZX: Tape format with knobs on. Able to handle all kinds of custom loaders
Z80: Snapshot format. Stuck in a game at a certain point? Snap it and
     continue later.
sna: snapshot format, falling out of use because Z80 is better.
