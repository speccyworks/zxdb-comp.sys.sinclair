Only one way to detect if it is 48 or 128 snap is to have an experience
and much to know about speccy games... It's because many games for
speccy 48 was snapshoted on speccy 128 under 128 mode. By this,
everytime, when you will load this snapshot in emulator, the you will get
128 speccy mode. And if it is .z80 snap file, then you can get more than
48 kb of size, because Speccy 128 cleans after reset only 48 memory.
So if somebody load game on 128 mode and then snaped it, emulator
store 48 game with some 128 page, because there was still something from
another game, in them... Many of this mistakes are (or was) on World Of
Spectrum... :(


And .tap and .tzx ?  Only one way to detect it is load them in both (48 and
128)
mode and then watch if there are something different (ay music, extra
graphics...)

2000-12-04 Philip Kendall Re: Snap formats...
"Ian Griffiths" <…@…> writes:

> I've been trying to work this out for a while - is there any surefire way of
> telling what format (48/128) a snapshot, tape file, tzx file etc. was
> originally captured in?

[I _think_ what you're trying to find out here is whether a program
image was from a 48K or 128K machine (or possibly even
+2/+2A/+3/etc). If not, this answer won't be too helpful...]

* Snaps: generally, yes. To run through the ones listed in the FAQ
  (or at least, those which have the possibility of 128Kb snaps...)
  * .sna: file size: 48Kb snaps are 49179 bytes long, 128Kb snaps are
    either 131103 or 147487 bytes.
  * .z80: first look at bytes 6 and 7. If these are non-zero, it is a
    .z80 v1.45 file and always 48Kb. If these are zero, look at byte
    30; this will (hopefully) be 23 (for v2 .z80 files) or 54 (v3).
    Now reference your hardware type by the table given in
    techinfo.doc and/or the FAQ. (Also note the possibility that byte
    30 may be 55, which signifies xzx's extensions - see the FAQ).
  * .zxs: decode the block structure until you find the 'fmtz' block,
    then it's easy...

  (SnapConv (GPL) has source for doing all the above </plug>)

* .tap files: basically, no -- the same data would be produced by a
   48K or 128K machine.

* .tzx: as previously mentioned, it's possible to create information
  blocks in .tzx files, which would at least tell you something. But
  generally, no.

HTH (at least a bit!),

Phil
