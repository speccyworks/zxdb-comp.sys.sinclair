A good trick I know is to use OVER 1 and PRINT the header after the
SCREEN$ has loaded. Then set the cursor position so that the actual header
will be printed over that and, like magic, it will disappear! So the
loader might look something like this (the following is probably
bug-ridden because I don't have a Spectrum at hand to test it on, but a
bit of hacking should certainly produce the desired effect):

10 LOAD "" SCREEN$
20 OVER 1
30 PRINT AT 1,0;"Bytes: game"
40 PRINT AT 0,0;
50 LOAD "game" CODE

An alternative for more sophisticated Spectrum users who are familiar with
the method is to save and load the code by calling ROM routines directly
(1218 and 1366 if I remember rightly - but they can't be called directly
from BASIC, the calls need to be preceeded by machine code to set up the
registers), bypassing the file header altogether.

1999-03-29 16:29:24 …@… Re: POKE to prevent program name display ZXDB: Program Name
Andrew Broad entertained comp.sys.sinclair with the following story:
>96171975 wrote:
>> Can anyone tell me the POKE that can be used to stop the names of files
>> loading being displayed?

Under normal circumstances (which includes not having an interface 1),
POKE 23739,111 will temporarily stop screen output.  This lasts until
either you clear the screen or you poke it back to 249.

For this to be more general you should instead POKE the address:
PEEK 23631+256*PEEK 23632+5
(which you should find is equal to 23739 in the same normal circumstances as
referred to above).

>A good trick I know is to use OVER 1 and PRINT the header after the
>SCREEN$ has loaded. Then set the cursor position so that the actual header
>will be printed over that and, like magic, it will disappear!

An old trick is to design the loading screen with a horizontal black stripe
cunningly hidden in it.  Then say "INK 0: PAPER 0" and use a PRINT AT to
make sure that the program name will be printed over the black stripe, thus
making zero difference to what's on the screen.  The stripe needs to start
at the left hand edge because the Speccy always prints a carriage return
before saying "Program: whatever".
