the ZX Spectrum SE has now reached the stage where I feel I can let you have
a look at it. I'm posting it on alt.binaries.comp.sinclair right now, but it
should also be available to download from the ZX Spectrum SE site
(zxse.raww.net) later this week. If you can't get ABCS and you can't wait,
email me and I'll send you a copy. Here's the documentation:

What's in the package?
     
---------------------------------------------------------------------------
There should be three files:

README58.TXT - This file
BAS0_58B.ROM - SE Basic v0.58b1.0
128PATCH.ROM - The 128 editor ROM, patched for use with SE Basic.
SE42DEMO.SCR - A screenshot of the new font in 42 column mode.

If you wish to distribute SE Basic, you must include all these files!

Should I report bugs?
     
---------------------------------------------------------------------------
SE Basic is a development of the original Spectrum BASIC by Steven Vickers.
I have attempted to debug it, while adding functionality without breaking
any existing software. Please send bug reports to …@….
So far, there are only two known issues; The menu screen on Auf Wiedersehn
Monty is slightly corrupted due to the new font, and Travel With Trashman
refuses to load because it tests to make sure you are using the original
ROM (a snapshot made after loading will with the original ROM will work).

What's new?
     
---------------------------------------------------------------------------
The keyboard works differently in Basic

Added a tokenizer, doing away with keyword entry.
Shortcuts are still available for LOAD, RUN & STOP (SYMBOL + Q, W, & E).
Removed EXTEND MODE for everything except control codes.
All SYMBOLS now available via two-key combination.
Allowed the cursor to move up and down while editing a line.

Some commands are different

Replaced CAT, CONTINUE GO TO & GO SUB with DIR, CONT, GOTO & GOSUB.
Extended the NEW command; NEW or NEW 0 = Warm Reset, NEW 1 = Cold Reset.
Modified the PAUSE command; PAUSE is equivalent to PAUSE 0.

Basic has been extended

Increased the line number range to 16383.
A new font; Geneva-6, which supports 42 column text.
A more efficient initialisation routine.

There are some background changes you might not notice

Changed the characters produced by [G] mode + V to Z.
Implemented a 16K test (needed because of the new initialisation).
Speeded up the pilot signal syncronization by four times.
Made the cursor inverse (only visible in extended screen modes).
Changed the RASP duration.

Every known bug that can be fixed has been fixed

Fixed the -65536 bug.
Fixed the CHR$ 8 bug.
Fixed the CHR$ 9 bug.
Fixed the CLEAR-PRB bug.
Fixed the CLOSE #4 bug.
Fixed the colour commands bug.
Fixed the DEC-TO-FP division bug.
Fixed the double store bug.
Fixed the EDIT bug.
Fixed the leading space bug.
Fixed the LIST bug.
Fixed the MAIN-4 bugs.
Fixed the MOD-DIV bug.
Fixed the NMI bug.
Fixed the PLOT bug.
Fixed the PR-CC bug.
Fixed the PO-FETCH bug.
Fixed the RESTORE bug.
Fixed the ROM overwrite bug.
Fixed the ROM scroll bug.
Fixed the RUN/GOTO/GOSUB bug.
Fixed the stack bug.
Fixed the WAIT-KEY bug.

What's planned?
     
---------------------------------------------------------------------------
This is the first version of SE Basic where all the bug-fixes are working.
It's taken nearly two years to get to this stage. Since there are no-more
bugs to fix I can now get on with extending BASIC further. I have several
ideas of things I'd like to do but I'm severely constrained by the
available memory. I will probably end up shortening the error messages to
make a bit more room. The additions I am considering are as follows:

21 new characters available via the UDGs; the Euro symbol, various
accents, a few mathematical characters etc.

Built in support for 42 column text.

Built in support for 512x192 mode on Timex and Pentagon.

A faster CIRCLE routine.

A default NMI routine allowing LOAD/SAVE snapshots and POKE memory.

If you have any suggestions for other improvements you would like to see
please send them to …@….

-Andrew Owen, January 1, 2002.

The problems are that the GPL requires that licensees allow the code,
along with whatever other software is needed to make it work (except
the operating system it will run on) to be freely distributed without
restriction.

The restriction that derived works of the Amstrad ROM can only be used
for non-commercial purposes contradicts this.  If Andrew is the sole
author (except for the Amstrad bits), he can distribute it how he likes,
but if he puts the GPL on it, no-one who gets it can then distribute it,
as they would be breaking either the GPL or Amstrad's copyright.

The solution is for Andrew to use another license - LGPL, BSD, whatever.

If Andrew's work contains or is derived from other work which he has
obtained under the GPL, he can't do that, and will have to replace those
bits in order to distribute his work.  That is the point of the GPL.

It might be possible to work it somehow using the "operating system and
components normally distributed with it" exception.  Andrew's product
would have to be packaged as an enhancement to run on actual Sinclair
computers, and be distributed without Amstrad's code in it - e.g. as
a package that copies the system ROM and patches it.  If the package
is intended to run on an actual Sinclair, the original ROM is clearly
part of the operating system, and does not need to be included in his
distribution or available under the GPL.  If the package can also run
on a Sinclair emulator, that's no big deal - the point for GPL purposes
is that the package is useful without any restricted third-party code.

I'm not 100% on that, and it feels a bit like cheating, and I haven't
gone back to the exact wording of the Operating System exception clause
in the GPL to check it, but it seems like a possibility.

The following will do the job in either direction:

#! /usr/bin/perl -w

die "$0: usage: $0 <ROM image> <ROM/EOR image> <output EOR/ROM image>\n"
  if $#ARGV != 2;

undef $/;

sub readrom ($)
{
  my $file = shift;
  open ROM, '<'.$file or die "$0: can't read $file: $!\n";
  my $rom;
  defined ($rom = <ROM>) or die "$0: can't read $file: $!\n";
  close ROM;
  return $rom;
}

my $rom1 = readrom ($ARGV[0]);
my $rom2 = readrom ($ARGV[1]);

die "$0: ROM images' sizes don't match\n"
  if length ($rom1) !=  length ($rom2);

$rom1 ^= $rom2;

open ROM, '>'.$ARGV[2] or die "$0: can't write $ARGV[2]: $!\n";
print ROM $rom1 or die "$0: can't write $ARGV[2]: $!\n";
close ROM or die "$0: can't write $ARGV[2]: $!\n";

exit 0;
