2002-02-06 17:30:48 Chris Cowley CSSCGC Crap Games Contest 2002
Inspired by some of the CSSCGC2001 entries which, frankly, are verging
on being not-crap-at-all (Eq Tetrachloride and Mike Wynne, you should be
ashamed of yourselves!), I thought it might be a good idea to have a CSS
Non-Crap Games Competition.

I propose that the rules should simply be:-

  1. No machine code! You can use any BASIC keyword you like, including
     POKE, PEEK, IN and OUT, but the only use of "USR" must be related
     to UDGs rather than calling machine code or ROM routines.

  2. You can use BREAK protection if you really want to, but there must
     be an easy way of turning it off (so the judge(s) can verify that
     the game is entirely BASIC).

  Errmm... That`s all the rules there needs to be I think.

So, what do people think? If there`s any interest, I`ll set up a
web-site and write a game or two to get the ball rolling (although I`ll
be excluded from the actual competition unless anyone else wants to
judge it).

I will even stump up suitable 1st, 2nd and 3rd prizes if I`m allowed to
have `sponsored by Grok Developments Ltd` logo on the site.

Opinions? How many of you would be willing to have a go?
-- 
Chris Cowley

Okay. If enough people want to do machine code or hybrid
machine-code/BASIC games then we can have two categories; a "pure BASIC"
category and a "uses machine code" category.

The thinking behind saying `no machine code` was mainly to keep a level
playing field and to encourage the non-Z80-coders to have a go, but also
to recapture some of the inventiveness of the better magazine type-in
games of the spectrums early years. I actually have one or two vague
ideas for what I hope will be reasonably playable small games that
should work okay in pure BASIC and I think trying to make them work in
BASIC will add to the challenge a little bit.

So to recap... There`ll be two categories; "BASIC only" and "Machine
Code". I propose that BASIC programs that call machine code routines,
and compiled BASIC programs, should be included in the Machine Code
category.

The prizes will be:-

  1. Best pure BASIC game: 75p and a packet of Rolos, plus a tacky
     laser-printed certificate.

  2. Best machine code game: 75p and a packet of Rolos, plus a tacky
     laser-printed certificate.

And the best overall game (i.e the best one of the above) will also win
a packet of Golden Wonder Nice`N`Spicy Nik Naks (in addition to untold
levels of glory and appreciation, obviously). I will try to work out an
online voting system so that even non-competitors can take part by
submitting ratings for each game (I`m thinking along the lines of marks
out of 5 for playability, looks, sounds, inventiveness, originality
etc.).

Everyone happy with that? If so I`ll knock up a website in the next few
days and get the ball rolling...

Do you think will people take it that seriously?! My only aim is to
harness some of the energy and enthusiasm that goes into so many of the
CSSCGC entries, and put it to use making games that people might
actually want to play for fun rather than just a few minutes of novelty
value.

and providing some reasonable prizes, but the more I think about that
the more it seems that that would encourage the wrong approach. Hence
the "75p and a packet of Rolos" prizes, which are completely genuine

produce a little game that happens to have some big graphical
backgrounds in it, or that has a sampled sounds or whatever, then I
wouldn't want to say "Sorry, that's too big. Strip it down and resubmit
it with fewer features, or fewer graphics" or whatever.

about this, but I really think you're needn't worry about having to
compete with the next Uridium or Head of Heels or whatever. It's just a
bit of fun!

and the outcome will be decided by an online voting system. Votes won't
start to be accepted until 1st November and people can submit improved
versions of existing games up-until the voting starts.

Web site to be announced soon (but probably after the CSSCGC2K1 winner
has been announced, as I don't want to steal anyone's thunder)!
