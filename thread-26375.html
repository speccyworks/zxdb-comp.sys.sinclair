ANN: ZX Spectrum SE is completed

2002-10-13 14:44:08 Andrew Owen 
Hi all,

Bet you thought it would never happen eh? Well, prototype one is finished
(well actually the AY isn't stereo at the moment but the circuit is). And
I ran SE Basic on it today without too much difficulty. I should point out
I'm not a hardware guru. I knew what I wanted and I got a very talented
speccy engineer to build it for me so please visit www.yarek.com if you're
interested in any of the mods (some aren't on the site yet as they were
designed specifically for the SE). So here's the spex:

Base machine: Timex Portugal TC2048

PSU: I'm using the PSU off a grey +2 just to make sure all the extra
hardware gets enough juice.

CPU: Z80A @ 3.528 MHz (as per TC2048)

ULA: Modified Timex SCLD. Total of 27K of memory usable by video chip.
Uses both ZX128 and Timex modes to give a total of 4x standard spectrum
screen, 2x hi-res screen or 2x hi-colour screen. standard mode is 256x192.
hi-res is 512x192 mono. hi-colour is 256x192 but attributes are in 8x1
cells instead of 8x8 cells.

Interrupts: can be physically disabled via I/O without a DI instruction.

Keyboard: One of those notebook size PS/2 keyboards in black via ProFace-AT.

Mouse: Amiga 2-button via built-in modified Kempston port.

Joystick: 2 button + autofire via built-in modified Kempston port. (bought
a new Konix Speedking from an Amiga supplier)

LED: Next to on off switch. RED = connected. GREEN = power on.

Soft-reset: CTRL-ALT-DEL via keyboard.

NMI: button added to original machine.

Memory: 280K. 144K in Spectrum 128 layout (extra 16K in place of bank 2).
128K in Timex horizontal memory (64K accessible at one time via DOCK or EX
banks). 8K EEPROM accessible via AY chip.

Sound: retro-fitted ABC/ACB switchable stereo AY circuit (currently wired
to internal speaker). Wired to ZX128 and TS2068 sound ports for maximum
compatibility.

ROM: Modified 128 editor (Resets Timex display, doesn't call TEST
routine). Standard 48K Basic. More compatible than original 128. Custom
ROMs can be used via DOCK or EX-BANK. (SE Basic works a treat). Traps for
TR-DOS emulation (not implimented).

Not really much of an upgrade in some respects, but rather more powerful
than it was in its original configuration, and more video modes than you
can shake a stick at. Plus plenty of memory. So what's next? I'll be
adding a ZXATASP hard disk interface. And then I'll be getting on with SE
Basic. And when that's out of Beta, I'll start work on the code behind the
GUI.

And how much did it all cost? I think I paid over the odds for the
original machine, but the parts were dirt cheap and Jarek charges very
reasonable labour costs. So if you want your own ZX Spectrum SE, visit
www.yarek.com and drop him an email. Plus, if you get a ZXATASP interface
then you won't need the Timex's shadow RAM to use SE Basic as it has its
own shadow RAM. The ZXATASP isn't one of Jarek's devices. I can't remember
the web address off hand but there's a link on the ZX Spectrum +3e site I
think.

Comments, questions?

The largest area of spare space is the 1170 bytes preceding the
character set. This, as early Spectrum adverts pronounced, 
was designated for the RS232/Network software.

http://www.wearmouth.demon.co.uk/GIF/advert.gif

Would it fit? Did they run out of room? I don't think so.

There are plenty of clues to suggest that the Spectrum was inputting and
outputting to these channels long before it went into production.

The "Sea Change" ROM is an attempt to prove that the concept of a "Real
World" Spectrum was viable. 

http://www.wearmouth.demon.co.uk/sc01.htm

I have fitted the RS232 and network routines from Interface 1 into the
spare space.  While I believe that the RS232 routines are the original
Spectrum routines (neither of the Interface 1 authors Dr. Ian Logan
(microdrives) or Martin Brennan (network) claim authorship), the network
routines are not those of Nine Tiles Networks who wrote the rest of the
Spectrum ROM.

It has consequently been a tight fit and in making space available I
have had to optimize some routines, a task in which I have been helped
by Andrew Owen and James Smith.  Some of this probably comes across as
nitpicking, but it is only that the end result would be so desirable
that this has been done.  

The Spectrum ROM author was quite capable of doing these changes 
himself and indeed some of them, like moving the end-calc routine to
space between the restarts and using two bytes of the space character as
the default line zero pointer had already been done in the ZX81 but were
reversed at the commencement of the Spectrum development as they are
cryptic and make the software harder to maintain.  

Above all, the Spectrum was intended as a professional development and
it is ironic that the Beta Test ROM was put into production.

A long-standing plan to release the debugged alpha ROM was scotched by
Nigel Searle.  Indeed, during development, the software would vary on a
daily basis and it is possible that the wrong Beta was chosen as the
basis for the ROM.  It is at odds with the manual and two years later,
in the Pitman Pocket Book, the author seems to be writing about a
different ROM he either wrote or imagined he'd written.

The Complete Spectrum ROM Disassembly points out a few unused routines,
most notably the ZX81 Name Routine, EACH-STMT, P-INT-STO but misses 
REC-EDIT which was used in the ZX81 and ZX80 from which the Spectrum 
was developed.

Success to your project,
