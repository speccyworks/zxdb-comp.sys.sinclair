This will be the final message on this topic :)  I've
optimized and polished things off to my satisfaction and
I've let it loose on alt.binaries.comp.sinclair.

What's in the zip file:

* Three versions of the sprite software for:
- the spectrum, 256x192 pixel, 32x24 colour
- the ts2068/tc2048, 256x192 pixel, 32x192 colour
- the ts2068/tc2048, 512x192 monochrome

* One demo for each version.

Each version of the sprite software features:
- software rotation for pixel precise graphics
- any size, any number sprites (though performance
varies inversely with number, naturally!)
- fast background tiles, the same size as a char
- a dynamic block memory allocator


Enjoy,

Geoff Wearmouth, being an all-around nice guy, has kindly agreed
to host it.  You can get it from:

http://www.wearmouth.demon.co.uk/sprite-pack11.zip

Features:

- pixel-precise masked sprites, any number, any size though
  performance is inversely proportional to both attributes.
- background tiles.
- dynamic block memory allocator.
- versions for the spectrum, the ts2068/tc2048 hi-colour mode and
  the ts2068/tc2048 hi-res mode.

All source is included, plus a fully documented API and a short
batch file (in place of a makefile) that will automatically
generate a tap file directly from the source.

The engine should be fairly easy to use they way it is now
(I think). There are still a few things that should be done to
'complete' it:

- change 8-bit address increments to 16-bit to eliminate the
  256-byte memory boundary constraints (background tile definitions
  and sprite bitmap definitions can't cross these boundaries for
  this reason).  Increments were done this way to save a few cycles,
  but the benefits are dubious next to the hassle of making sure
  things stay inside a 256 byte block.  This option should be
  user selectable at assembly time with an 'ifdef' type guard.
- add an 'OR' type sprite as an alternative to masked sprites.
  Should more than double sprite drawing speed.
- add support for blocks of background tiles that allow pixel-
  placement on screen.  This would help in generating smooth-
  scrolling backgrounds and background-level sprites.  Right now,
  much of the dirty work is up to you.
- add a music / sound effects module.

And then you could always go nuts and add an ability to draw
on sprite surfaces.  That would mean you'd finally have a version
of Windows that didn't bluescreen every other day :)
