ZX81 16K RAM Pack shows 0.5K

7 posts, 2004-07-24 – 2004-07-28

2004-07-24 22:35:17 Martin Ancher Holm ZXDB: 16K RAM Pack
Hi!

A few years back I got three 16K RAM Packs and a ZX Printer together with
some other old stuff. I've never had a ZX81, though several times I
thought it would be cool to find one of these old devices at a garage
sale, but it never happened. The 16K RAM Packs were just put in storage
for fun.

A week ago a friend of mine told me there was a ZX81 on QXL (web-auction)
and since I'd talked about ZX81 several times, he'd just mention it.

I made several bids and now I have an unused ZX81 for apx. 45 GBP - Yes!

I've tried ZXC.EXE and loaded 1K Chess and 1K Breakout and both works
fine. Cool, but I wanted to try Softwarefarm's Forty, so I found my three
16K RAM Packs in the basement.

Together with the 16K RAM Packs was a sheet of paper:
"ZX 16K RAM Pack - Instruction for use".

On that sheet of paper was this program:

MEMORY TEST PROGRAM
1 POKE 18000,33
2 POKE 18001,11
3 POKE 18002,0
4 POKE 18003,57
5 POKE 18004,68
6 POKE 18005,77
7 POKE 18006,201
8 PRINT (USR(18000)-16373)/1024;"K"

When I run the program without any RAM Pack it displays:
1K

When I run the program with a 16K RAM Pack it displays:
0.5K

Anybody know what's wrong. The small 1K programs won't load with the
16K RAM Pack, so I guest the program is right, when it says: 0.5K. :-(

Any thoughts?

For all three RAM Packs to give the same result I would say that one of
the address lines on the edge connector needs cleaning. I have bought
non working interfaces from ebay that have worked after a clean.

The 1K internal RAM is not used when the RAM Packs are fitted.

I am sure there are people here that could tell you exactly which pin
needs cleaning and whether it is on top or on the underside.

2004-07-25 06:34:42 Brian Gaff Re: ZX81 16K RAM Pack shows 0.5K
This was common when the edge connector was dirty. In my old machine I ended
up taking it apart t o clean the damn thing, as I recall. However, if you
got the ram packs from some end of run, they could probably all be user
returns with the same fault.

You need to find a known good one, even if you only borrow it, to make sure
the fault is not in the 81.
