2008-01-06 13:43:44 Nama ZXDB: Chopper Drop 3000
Hi everyone,
It's been a long time coming, but it's finished.

Introducing a brand new game for the 16k ZX81, and the first ZX81 game
release for 2008.

CHOPPER DROP 3000

The game was co-written by myself and Andre***. I did most of the
original coding, graphics, and animation. Andre*** streamlined much of
the code and allowed the game to be very playable on a stock 16k ZX81.
However, if you have an emulator that can emulate the ZX81 at a faster
speed, I highly recommend that you give the game a go accelerated. You
won't be disappointed.

The Game: You are the pilot of the RODO 3000, a highly advanced
military helicopter. Your mission is to destroy all the attacking
tanks. You are also being attacked from a high flying UFT which drops
bombs from above.

There are both English and French versions in .p format available from
here:

http://tinyurl.com/2fpasj

or here:

http://homepage.mac.com/WebObjects/FileSharing.woa/wa/default?user=lord_philip&fpath=Maplin%20Projects&templatefn=FileSharing6.html

Finally, I wanted to thank Andre*** for all his time and effort. It
was fun working with him on this project and I certainly learnt a lot.

Please download and enjoy.

Philip

2008-01-19 09:21:36 siggi Re: ZX81 Chopper Drop released
Hi Philip and Andre***

you really made a nice game for the good old Zeddy. And because I like
to play Zeddy games on a Zeddy (not a windoofs pc with an emulator), I
had no chance tho increase the speed of the game (even Wilf's "nearly
no wait"-circuit does not help). There is so much action in that game,
that even Andre could not speed it up enough to have really action on
a real Zeddy.

So I took MCODER II and are now trying to compile that program.
I had to change some instructions, that were too complicated for
MCODER to understand (-> but Andre*** understands them ;-). And since
that compiler uses integer-arithmetic, I had to change some
calculations and to throw out the delay-functions "SIN" and
"COS" (replaced them by the integer-SQR).
Now the program compiles, but due to memory size the basic source and
the compiler use the 16K Basic ram, while the compiled code currently
runs above 32K.
And now the speed is like of those old ARCADE games ;-) and I probably
have to add some delay loops :-)

Hopefully I get the compiled program (without source) to run in the
normal Basic 16K ram.
Work is going on ....
