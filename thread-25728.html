Back in the dim, dark and distant past, Dave the Lurker waffled on about:

Well, I started by looking for an appearance of a loading routine. In
fact, the short "loader" routine is mostly that. There are a few sneaky
bits in it - it loads bits of itself throughout the loading process, for
example.

The loading routine is very similar to the one in the ROM - can't
remember the address offhand - but the first 9 bytes of each "block"
contain the start and length of the following one:

F630 LD IX,#F691   <- first nine bytes dest are set by the code
F634 LD DE,09      <- here
...
F681 RRC (HL)
F683 JP C,#F691    <- the Carry is set when the loading is done for that block
F686 LD IX,#F691   <- first nine bytes contain our future dest and len
F68A LD DE,09      <- but these two are the dest and len of those bytes
F68D XOR A
F68E JP #F69A
F691 NOP           <- here is where we jump to from above
F692 NOP           <- and is where the LD IX above points to
...

Now each block has another 9 bytes at the start which are placed at F691,
and then executed. The first one, for example has:

F691 LD IX,#5900
F695 LD DE,#0100
F698 LD A,#00

(Dunno what's at #5900 though, can't remember). The loop starts again,
and it then loads #0100 bytes at #5900. The very last bit is JP #7512,
which starts the game. (The RANDOMIZE USR 29970 in the original BASIC
loader) I don't think the LD A,0 was needed, but I might be wrong. 

All I did was change that JP C,#F691 to JP C,#F700. At #F700, I put a
little routine to see when the JP #7512 was loaded:

F700 LD A,(F691)
F703 CP #C3
F705 JP NZ,#F691
F708 EI
F709 RET

Once the code for JP #7512 is loaded, my code notices it, and instead of
running it like normal, it just returns to BASIC. 

This wouldn't work if the loading routine had blitzed the BASIC area or
the system vars, but luckily, it doesn't.

There was also a LD SP,<something> which I just NOP'd out. Note that I
had to EI before the RET to BASIC. If you've not got interrupts enabled
when you return, the Speccy is running fine, but is useless as the
keyboard won't work..! (How many times have I done that?)

Woo.. long post! Hope some of it is useful...!

This is much longer than I originally intended, but anyway:

10 CLEAR 32767: LOAD ""CODE
20 LET B$="ED5FAE77230B78B120F6"
30 LET A$="F33E4DED4F21E9FE010B017EAC85 L77230B78B120F621F9FE01FB00"
40 LET A$=A$+B$+"2109FF01EB00"+B$+"FBC9"
50 LET B=32768:GO SUB 1000
60 RANDOMIZE USR 32768
70 CLS
80 LET A$="E5F5DDE5E13AFDFFCB7F280A7CFEFF280BA7FE583806F1DD77001801F1E1C34FFF"
90 LET B=16384:GO SUB 1000
100 LET A$="CB0ED26EFF3A78FFFEDDCA78FF31FFFFFD213A5C"
110 LET A$=A$+"21AE733600": REM INFINITE LIVES
120 LET A$=A$+"21E8863600": REM NASTY IMMUNITY
130 LET A$=A$+"21ED863600": REM NO GHOSTS
140 LET B=20480:GO SUB 1000
150 LET A$="C30040": LET B=65356:GO SUB 1000
160 LET A$="C3005000": LET B=65386:GO SUB 1000
170 LET A$="FE31FF57C30AFF": LET B=32768:GO SUB 1000
180 RANDOMIZE USR 32768
1000 FOR A=0 TO LEN A$-2 STEP 2
1010 LET HI=CODE A$(A+1)-48:IF HI>15 THEN LET HI=HI-7
1020 LET LO=CODE A$(A+2)-48:IF LO>15 THEN LET LO=LO-7
1030 POKE B,HI*16+LO
1040 NEXT A
1050 RETURN

You'll note (if anyone bothers to type it in) that it modifies the loading
routine to ignore loading anything in the range 4000 - 57FF hex, so you 
get the attributes loaded on screen, but not the pixels. 

I had a lot of trouble with this because I was not really thinking
straight. I got this routine written last week, but because it uses PUSH
and POP, the loading would USR 0 half way through - because I'd forgotten
about the stack. In the end I had to put the stack on the screen - so
you'll see it flickering away to itself on the bottom.

The first RANDOMIZE USR 32768 actually decodes the loading routine; the
second starts the loading. You'll have to pause the "tape" between the
"loader" code and the speedload bit because the BASIC isn't quick enough
to do it all in the short space.

Source code:

org 32768
ld a,&87
ld (&ff0c),a

; after the decryption that &87 becomes &C3
; so at &ff0c we'll have JP &fffd

; so put a JP at &fffd back to 'trap1'
ld a,195
ld hl,trap1
ld (&fffd),a
ld (&fffe),hl
jp &fec3  ; run the decryption loops

trap1:
ld (&fffd),a  ;execute the op we originally altered

; copy the code at 'trap2' to &fe00 replacing what was the decryption
loops.

ld hl,trap2
ld de,&fe00
ld (&ff46),de  ; the code at 'trap2' will run after loading every byte
ld bc,trap2end-trap2
ldir
jp &ff0f  ; now run the loader

trap2:

; l=loaded byte on entry
ld a,(&ff78)
cp 195   ; have we finished loading?
jr z,rungame

; write the loaded bytes except when:

IX >= fe00 and <= fe78 or
IX >= ff00 and <= ff78

ld a,ixh
cp &fe
jr c,writeandcont
ld a,ixl
cp &78
jr nc,writeandcont

ld a,l
jp &ff4f	; continue with no byte write

writeandcont:
ld (ix+0),l  ; write the loaded byte
ld a,l
jp &ff4f

rungame:
ld sp,&ffff
ld iy,&5c3a
xor a
ld (29614),a	; infinite lives
jp &61a8
