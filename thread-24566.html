2002-02-20 13:03:28 Kevin Thacker 
Hi All,

I have started a archive of Amstrad TZX's along the same lines as the
TZXVault.
e.g. the files should be taken from originals for preservation
purposes.

I am also writing a document to help the authors of emulators so they
can support these files.

I have read the spec and there are some Spectrum and C64 specific
blocks.
I have listed the problem blocks and my suggestions.

ID:2A Stop the tape if in 48k mode

This block MUST be ignored, there shouldn't be any pause or anything.
It is suggested that block (ID:30 Text Description) should be used.
The emulator should allow the tape to be resumed from this point.

ID:34 Emulation Info

This block MUST be ignored. Some information doesn't apply to Amstrad
emulators.
The ID:33 hardware type, and ID:31 text description should be used to
describe why; but not prevent the user from actually trying the
program.

ID:40 Snapshot block.

This block MUST be ignored. The information doesn't apply to the
Amstrad.

ID:10 Standard Speed Data Block

Standard Spectrum loading parameters must be used.
Pilot Pulse: 2168, Pilot length: ?? what should I put here
Sync 1: 667, Sync 2: 735 etc

ID:16,ID:17 C64 blocks

SHOULD be supported to accuratly reproduce sound signal, but MUST not
be present in Amstrad specific CDTs. It is possible therefore to take
a tzx specific to C64 and use it on the emu, but don't expect it to
load ;)

ID:20 pause or stop the tape.

If "0", the tape should not be stopped. Play must continue, it is up
to the user to actually "stop the tape".

ID:35 Custom Info

Spectrum Screen Block, ZX-Edit document block MUST be ignored.
I'm not sure if picture block should be ignored as well (i.e. don't
display), but instructions is ok.

Hardware block:

0 = computers (is ok), 1-F applies to spectrum and should be ignored.

What do you think to this?

Regards,
Kev

The aim is that the same tape images can be used on all emulators,
with the same sound wave being generated.

I could use a Spectrum tape image with a Amstrad emulator, and I do

I can understand that with TZX, that to describe more signals that

In a way this block is just a helper and doesn't relate to real life.

In real life on the Spectrum (48k), the cassette recorder wouldn't
stop. So if I forgot to stop it, I would curse and rewind it. On the
emulator, I should be able to do the same. To help me, there could be
some kind of indicator block
which I could use to "fast-rewind" back to the exact point. This could
be a text description, or it could be this block.

On the Amstrad it wouldn't actually stop unless the computer indicated
it should stop.

My preference would be to not include the screen.
If a screen is wanted then it should be included as a .gif/.png etc in
the zip archive that the cdt/tzx is distributed with.

The trouble for the Amstrad is that the screen dimensions and position
can be defined using the 6845 CRTC, and some very complex screens are
possible. I wouldn't want to attempt to describe a block which could
reproduce this. The best solution would be a picture dump taken using
the emulator itself.

> and mentioned using the Text Description.
Only to make it crystal clear what in my opinion should be done. I am
trying to anticipating some questions that the Amstrad emulator
author's will have.
 
> Anyway,  I'm glad that other people are interested in the TZX Format and
> maybe one day
> it will be enhanced to cater for other 8-bit tape systems.
I think it is a great format; and ideal for describing loaders.

The aim of the doc was to advise tool makers and emulator authors
about the way to handle TZX/CDT's and allowing TZX's made for other
computers to also be supported.

I am trying to promote it as much as possible. At this time there are
only
3 emulators which support it: CPCE (http://cpce.emuunlim.com/), Arnold
(http://arnold.emuunlim.com/) and Multi-Machine.

The other two major emulators, Caprice and Winape don't support it
yet. :(

But, there is a growing collection of tape images already. There have
been a core group of about 5 people doing the transfers, but we are
already being
held back by the lack of support for Amstrad speedloaders and a lack
of a Amstrad specific tool :( But I hope that will change soon as the
tools mature.

> Let me know the URL as I might be able to TZX/CDT some tapes for you.
all are welcome :) I prefer that they are not beautified. I believe
that you wouldn't do this anyway ;)


I am not trying to cause a argument. TZX is a good format, and can
describe the signal well, so that it could be used to reproduce the
original tapes if required.

I was just wanting to clarify some parts of the spec for Amstrad and
other users, especially since some is geared towards Spectrum (mainly
because of the enthusiasm and usage in that field). I also want to be
able to allow the tape images to be used with other emulators, and the
same signal to be reproduced. I appreciate your help with this. In the
end, my ideas are only suggestions, but if they help people to adopt
this format on the Amstrad, then this is good.

Regards,
Kev
