First some numbers:

    2: years since the ZX Spectrum SE was released
    1: ZX Spectrum SE's built including the original prototype
    1: emulators with ZX Spectrum SE support (FUSE)
    3: authors of ZX Spectrum SE specific software
    5: ZX Spectrum SE specific software releases

Given the relative lack of popularity of the ZX Spectrum SE you may
well be asking why the ZX Spectrum SE/CF should be any more successful.

Despite the fact that people have been talking about making a new
Spectrum since this newsgroup began, only a few dedicated hobbyists
have the technical know-how to do it, and because most people are not
willing to fork out the large amount a short-run machine would cost a
new physical Spectrum remains unviable.

Emulator authors as a rule, for their own reasons, are unwilling to
emulate non-existent hardware, which precludes the creation of a
virtual 'Super-Spectrum'. The exception to this rule is the Spec256
emulator - which proved what a waste of the emulator author's time
adding such support was when hardly anyone used the extra colour
feature.

The ZX Spectrum SE/CF is different. It is available as real hardware:
(ZX Spectrum SE + ZXCF interface), which is sufficiently documented to
allow consistent support across emulators. It is available in
emulation: FUSE emulates the ZX Spectrum SE/CF now. Just select the
Spectrum SE model and activate the ZXCF interface and you have a
working ZX Spectrum SE/CF environment.

Sounds too good to be true - it is. At present you still have to
install ResiDOS and set up the IDE file yourself, and unless you save a
snapshot you have to do this every time you start FUSE (unless I've
missed an option somewhere - which I may well have).

So here's the news - I am fixing the ZX Spectrum SE specification to be
exactly the same as the FUSE implimentation. This uses a 32K ROM, and
there is no 8K PRAM on the AY chip, but is otherwise as documented
here:

    http://www.sinclairfaq.com/cssfaq/reference/sereference.htm

The ZX Spectrum SE/CF requires a conforming ZX Spectrum SE and ZXCF
emulation. ZXCF is currently emulated by FUSE and RealSpectrum. Further
details here:

    http://user.tninet.se/~vjz762w/ZX_SPECTRUM_DIY_PROJECTS/zxcf.html

FUSE supports the new .SZX snapshot format, and the new .HDF hard disk
format. In order to make using the ZX Spectrum SE/CF as painless as
possible I intend to provide a BOOT image in .SZX format and a default
.HDF file as soon as I am able. These will be available from the ZX
Spectrum SE site:

    http://zxse.raww.net/

In the meantime here is the specification:

    Codename:  Jenny
    I/N:       TC31296
    CPU:       Z80A @ 3.528Mhz
    IDE:       ZXCF
    DOS:       ResiDOS (currently v1.84)
               http://www.zxplus3e.plus.com/residos/
    ROM:       32K
               ROM-0: 128 EDITOR (patched)
               ROM-1: 48 BASIC (original)
    Total RAM: 1,296K
               1MB ZXCF-RAM, 144K 128-RAM, 128K Timex-RAM
    Video RAM: 27K
               Lo-res: 256x192 (8x8 attr) - each screen uses 6.25k
               Hi-col: 256x192 (8x1 attr) - each screen uses 12.5k
               Hi-res: 512x192 (mono)     - each screen uses 12.5k
    Sound:     AY-3-8912

The ZX Spectrum SE currently supports software written for the
following machines:

    ZX80, ZX81, ZX Spectrum, Interface II, Timex 2068, ZX Spectrum 128,
BBC Basic (Z80)

One aim of the ZX Spectrum SE/CF is to allow IDE access in all these
modes, initially for BASIC programs only (ResiDOS currently only
supports 48K snapshot files).

If anyone would like to contribute to the project, particularly
converting the emulators to work under ResiDOS, I'd love to hear from
them. I'll read any comments posted here and take them onboard.

Good point. One of the ideas behind the ZX Spectrum SE was to create a
new standard. After all there's not much incentive to develop software
that will only run on one emulator. To succeed where Spec256 failed,
any new graphics standard would need to be adopted by at least these
emulators:

    FUSE, RealSpectrum, Spectaculator, SPIN, vbSpec.  

The authors of these emulators have all been forthcoming in sharing
information which has lead to some useful new features and standards,
notably:

    Built in SE Basic support
    ZX Printer support
    Timex TC2048 emulation
    Extended .SCR format for Timex screens
    New .SZX snapshot format
    ZX Spectrum SE emulation
    ZXCF, ZXATASP and +3e emulation
    New .HDF format[1] for IDE images 

Not all of these emulators impliment all of these features, and other
emulator authors have also shared information, but I think where they
lead others may follow. So, as I said, if anyone wants to discuss a
new graphics standard with me, drop me a line.

[1] An unfortunate choice of letters given that there is a
Hierarchical Definition File format that is *apparently* sometimes
used to contain hard drive images. Perhaps HZX would have been better.
