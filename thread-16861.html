1999-12-13 23:00:28 …@… Re: Format converters...
Equin0x (…@…) wrote:
: On 13 Dec 1999, Niall Tracey wrote:

: > Why isn't there a standard filter/loader-plugin format that allows
: > any emulator to use someone else's format filters?

: Different formats contain different information. For example, TAP contains
: multiple files whereas SNA, Z80 do not. On the other hand, snapshot
: formats save state (registers, devices attached, etc.), which tape-stream
: formats don't.

I'm well aware of this - I know multi-loaders are restricted to tape
archives, but I reckon it must be fairly simple to write a loader that
loads the majority of snapshots into a loadable file.

The best way to do this would be to write a cut-down version of one of
the emulators that supports all file formats in C (to make it
compilable on as many systems as possible) and loads the file into
memory, then writes the output snapshot as the image appears directly
after loading, either as a snapshot file or a 'trained' tap/tzx
file. This would help solve the annoying little quirk of many
snapshots that they open with an intro tune in the middle of the
second bar...

: The best idea is probably to decide on one standard format with the best
: features (probably a tape-stream with compression; TZX might come close)
: rather than every emulator creating a new format and each one having to
: deal with differently named and typed files. That said, the emulator scene
: is almost exclusively amateur-driven, so this isn't likely to happen.

Yup. Ain't that the way it goes.

I disagree on one count. There should be several standard formats:
  One tape       - TZX
  One snapshot   - Because people will always want mid-game saves.
  One microdrive - There is only one anyway, isn't there?
  One for every type of disc that ever existed.
