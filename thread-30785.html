It's simple. The cyan/red bars are a certain height. At the start of each 
frame of animation, you draw those bars starting at a lower height 
(increment the position) than the last frame. When you reach the height of 
the bars from the top, you move back to the start. This way, you get the 
bars scrolling smoothly down the screen.

Whilst doing this, at each frame you add a small random amount to the speed 
that the bars move, or the number of pixels that they move per frame. This 
only has to be small - 0.5 pixels up to about 2.5 pixels IIRC. This gives 
the "old tape" look.

I'd send you the source but I no longer have it.

I was pleasantly surprised to find that the screensaver still works fine 
here under Windows XP, and still looks a lot better than the competition 
that was around at the time. Has anyone else written any new speccy 
screensavers recently?

SPIN does that, yes, but Screen$ doesn't - When I'd started writing Screen$, 
I had never looked at my own emulator (SPIN and BASin were far into the 
future) and so I programmed Screen$ to build the tape images and sounds from 
the .scr file, by watching RealSpectrum closely and using a hex editor on 
WAV files made by it. I had no idea how to understand z80 assembly at the 
time, so couldn't figure out how the ROM loader worked, so it was all "try 
and see" - the main breakthrough came when I found that there was a yellow 
*and* a blue bar per tape edge, not one.

At that point people started "hearing" the loading sound in their heads, 
even before I had implemented the sound, and I knew I had the visuals right 
:)

To my mind, Screen$'s pilot tones are too short - but again I had no idea 
what a TState was when I wrote it, so the TZX file format was useless to me.

I'm sure that Phil suggested I read the FAQ at one point, but it was all 
senseless garbage at the time :)

The tape effect is made graphically, yes. The screen files are stored as 
.scr files - a straight dump of the memory from address 16384, for 6912 
bytes. Nothing like a TZX :)

I use the data, along with a knowledge of the ROM's timings to build the 
sound on the fly. There is *some* randomising of the output, but only to 
slightly "fuzz" it.

If you read the TZX spec, you'll see that the pulses used (or edge lengths) 
are of varying TStates lengths. You then work out how much of the border the 
speccy can display in that period of time. It works out to be between 3-4 
and 8-10 scanlines (from memory, very roughly). So you just switch the 
colour you're using after that period of time.
